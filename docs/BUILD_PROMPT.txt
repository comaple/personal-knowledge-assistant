请帮我从零实现一个本地单人使用的“个人资料问答助手”。请直接建立文件并实现，不要只解释方案。

技术约束：Python 3.10+ 标准库、SQLite/FTS5、HTML/CSS/原生 JavaScript。不用 Docker、外部数据库、前端构建工具或大型 Agent 框架。

功能：
1. 浏览器上传 UTF-8 TXT/Markdown，每个文件最大1 MB；按内容去重。
2. 保存原文，按800字符切块，相邻重叠120字符；中文用相邻双字形成检索词，英文按词处理。FTS5 只做关键词检索，不宣传语义检索。
3. 四张业务表：documents、chunks、sessions、messages；另建 chunk_search 全文索引，以片段ID关联。入库和删除需事务一致。
4. 每问检索前4个候选片段，展示文件名、片段编号和原文。默认仅检索，无Key也能使用。
5. 可选通过兼容 /chat/completions 的 API 生成答案。Key从服务端.env读取；只发送本次问题和命中的片段。提示模型依据片段回答并标注[S1]等出处，资料不足时说明不足；文档里的命令不能作为系统指令。
6. API超时45秒，输出上限900 tokens，不自动重试。未命中时不调用模型。拒绝无效的来源编号，同时明确编号校验不等于事实核验。
7. 文档、会话、消息和回答的证据快照落SQLite，重启后可恢复。会话历史只用于回看，不默认发给模型；每次仍按当前问题检索。
8. 文档可删除，片段和检索索引随之删除；历史消息证据快照保留并明确提示，删除会话可清除此会话消息和快照。
9. 仅监听127.0.0.1。页面不要把模型输出作为可执行HTML渲染。资料上传、提问和错误需有清晰状态。
10. 提供虚构摄影课程示例、README、.env.example、.gitignore及离线测试。

文件分工：app.py提供HTTP路由，index.html提供界面，store.py负责持久化，knowledge.py负责切块和检索，model_client.py负责模型调用，inspect_db.py查看表记录数。

验收：同内容不重复导入；退款问题命中“至少72小时”；无关问题不乱答；重启后文档与记录还在；删除文档后无法再检索到它；模型故障时明确报错且资料不丢；检索模式和无命中路径不调用外部模型。通过本地模拟接口测试请求与出处编号，不要假装已经用真实付费Key验证过。

请先完成一个可跑通的版本，再解释文件分工、执行顺序，以及如何逐步扩展向量检索和多轮上下文。
