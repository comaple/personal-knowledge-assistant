## 01｜验收对象与规则

本文件维护验收计划、执行结果及需求追溯。验收对象是个人知识管理助手，覆盖资料管理、知识组织、多路检索、图谱、DSH 问答、持久化、导出及故障处理。

- 当前只完成文档编写和文档静态检查；下文所有功能用例均未作为新版本执行。
- 已发布实现参照为 `4a571afbf426f75e9ff3bdf8a9b2970e2d3ad1da`；本地另有未提交原型。它们不是本次完整功能验收通过的依据。
- 执行前固定代码 commit 和工作树状态；含未提交代码的结果只能绑定该原型快照，不能声称对应公开仓库同名版本。
- 每个用例必须记录预期、实际、状态及证据。只看到 HTTP 200、模型声称完成或测试框架退出成功，都不足以单独判定产品通过。
- FR-13—FR-15 确定纳入首版后，其用例转为必验；范围未定时不得默认为通过或删除。

### 状态约定

| 状态 | 含义 |
| --- | --- |
| NOT_RUN（未执行） | 尚未执行；不是通过 |
| PENDING_SCOPE（范围待定） | 候选需求待确定；进入确认范围后必须验收 |
| PASS（通过） | 预期全部满足且有对应证据 |
| FAIL（失败） | 已执行但至少一项预期不满足 |
| BLOCKED（受阻） | 缺实现、依赖、服务或环境，无法执行；记录原因及恢复条件 |
| SKIP（跳过） | 本轮主动未执行；记录理由，不能计入完整通过 |

## 02｜验证层次与运行前准备

| 层次 | 验证内容 | 可以证明什么 |
| --- | --- | --- |
| L1 | 文档、静态检查、输入/事务/版本等必要单元验证 | 规格一致性及受测局部行为 |
| L2 | 真实 DSH、LightRAG 和存储后端，使用脚本模型与模拟向量 | 工具、协议、图谱和持久化链路；不证明真实模型效果 |
| L3 | 实际模型与实际 Embedding 服务冒烟 | 指定服务/模型/配置可连通，能完成约定流程 |
| L4 | 冻结题集的检索和回答质量、延时、费用评估 | 当前资料集与配置下的实际使用效果，不外推到所有资料 |

执行前准备：

1. 使用测试数据库和专用索引目录，不修改用户日常资料；需要从旧库迁移时先保存副本。
2. 记录操作系统、Python/SQLite/Node 版本、依赖版本、代码 commit、语料摘要和 profile。
3. 区分无 Key、本地模拟服务、真实服务三种配置；证据只记录是否配置 Key，不记录 Key 值。
4. 真实服务验证前确定模型、Embedding 维度及费用预算；未配置时相应用例保持 NOT_RUN 或 BLOCKED。
5. 为删除、编辑、超时和构建失败场景准备独立数据，避免用例互相污染。

## 03｜固定资料与测试问题

基础资料使用虚构内容，至少包含两份有联系的文档，以及一份无关文档：

- D1《摄影课说明》：摄影课相关事务联系青松教务。
- D2《教务服务说明》：青松教务受理退课，需在开课前至少 72 小时提交。
- D3《摄影作业要求》：课程作业的独立说明；完整正文在执行前冻结，避免与 D2 互相覆盖。

基础问题包括直接关键词、不同措辞的同义问题、跨 D1/D2 的问题，以及资料没有答案的问题。跨文档示例为“摄影课退出申请最晚什么时候交？”，预期证据是 D1 与 D2；不能只核对回答是否包含数字 72。

笔记与标签用例另外新建“项目记录”笔记，设置“项目”“待整理”等标签；编辑时将测试文档中的 72 小时改为 48 小时，用于核对索引失效及历史引用快照。此修改仅用于独立测试数据。

## 05｜执行方式与证据

以下是后续候选命令，均从仓库根目录执行。当前发布基线未包含所有原型测试文件；目标版本缺文件或依赖时，应记录缺口，不能把命令未运行算作通过。

```bash
# Python：业务、事务、索引及检索链路；完整图谱用例需要安装对应依赖
python -m unittest -v test_project.py test_rag

# Node：真实 DSH 运行时配合模拟模型服务
npm run test:harness
```

图谱与 DSH 集成需要同时具备 Python、LightRAG 和 Node/DSH 依赖。没有 LightRAG 时部分用例可能跳过；应逐项核对，不只读取最后的 OK。UI 脚本若仍在未提交原型中，应先在实施任务中决定是否交付，不能作为干净仓库必有的入口。

真实服务验证与人工界面验收单独执行；上述命令通过不自动完成 L3/L4。接口返回正确还需核对数据库状态和实际工具结果。

证据至少包括：

- 运行命令、退出码、通过/失败/跳过数量、开始与结束时间。
- 目标 commit、配置 profile、语料 revision、测试数据摘要。
- 关键 HTTP 响应、数据库断言、工具调用与结果对应关系、必要的界面截图。
- 真实模型和 Embedding 标识、用量/费用的可得记录及人工来源核对。

原始日志在专用测试输出目录保存，索引文件和真实资料不随文档自动提交。仓库仅提交脱敏的验收摘要与必要证据；报告中的路径或 URL 必须能对应实际产物。

## 06｜真实使用效果验证

质量验证针对个人资料查找和使用，不只考察答案是否流畅。

1. 冻结至少 20 题，覆盖直接关键词、语义改述、跨文档、无答案和冲突信息，人工标注应使用的原文与可接受结论。
2. 使用同一语料、模型和预算，分别评估 BM25、三路检索及三路加图谱工具流程。
3. 记录所需证据是否召回、回答是否得到原文支持、错误拒答/遗漏、耗时、API 用量与费用；候选上限和所需来源集合一并记录。
4. 先试测，再确定质量通过阈值；阈值尚未确定时记录“未完成质量验收”，不能仅靠平均分或示例成功给出 PASS。

| 指标 | 判定依据 | 当前结果 |
| --- | --- | --- |
| 引用 ID 合法率 | 全部引用 ID 属于本轮返回来源；目标 100% | 未测 |
| 版本一致性 | 不使用过期索引或混用旧/新来源；目标违规次数 0 | 未测 |
| 证据覆盖与回答支持 | 人工标准证据及逐题原文核对；阈值待试测确定 | 未测 |
| 延时与费用 | 每题实际耗时、用量及费用，报告环境和样本数 | 未测 |
| 知识可迁移性 | 导出内容在系统外可读且元数据对应；候选需求确认后执行 | 范围待定 |

## 08｜当前结论与交付条件

当前功能验收统计：**18 项计划用例；15 项 NOT_RUN，3 项 PENDING_SCOPE，0 项 PASS。**这是验收计划状态，不是失败率或产品可用性评分。

- 文档静态检查仅验证目录、链接、示例格式和需求/用例追溯，不能据此宣布功能验收完成。
- 范围确认后的 P0 用例必须有执行结果和证据；FAIL、BLOCKED、SKIP、NOT_RUN 均不能自动算作完整通过。
- L1/L2、L3、L4 分开报告；真实服务或质量未验证时，交付必须写明能力边界，不能写“全部验收通过”。

- 只交付规格文档时，可发布本文的计划版本；这不代表产品已具备全部列出的能力。
