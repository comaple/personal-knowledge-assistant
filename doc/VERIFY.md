## 01｜状态与验证层次

功能用例状态为 NOT_RUN/PASS/FAIL/BLOCKED/SKIP。PASS 必须有对应提交、配置、数据和实际证据；缺依赖是 BLOCKED，主动未运行是 SKIP，二者均不能算通过。本轮已补齐L3/L4真实DeepSeek+BGE-M3及固定20题复验，详见[真实验收与启动记录](verification/REAL-REPORT.md)；此前L1/L2、干净检出、浏览器与本地性能验证见 [当前实现报告](verification/REPORT.md)。用例含多个子场景；仅验证部分时仍保留 NOT_RUN，并列出缺口，不把工程测试数当作用例通过数。

| 层次 | 内容 | 不能据此证明的内容 |
| --- | --- | --- |
| L1 | 文档/契约/DDL 静态检查及必要单元验证 | 真实服务和产品使用质量 |
| L2 | 真实 DSH、LightRAG、SQLite/向量后端 + 模拟模型/向量服务 | 真实模型决策、实际权重效果 |
| L3 | 固定实际模型/Embedding 的完整冒烟流程 | 所有资料上的普遍效果 |
| L4 | 固定 20 题的证据、回答、冲突/拒答、延时和费用 | 超出该语料与配置的保证 |

已有发布 CI、脚本存在或模型自报完成都不能直接改本文件结果。功能验收绑定后续目标代码 commit；未提交原型的结果不能标为公开仓库版本结果。

## 05｜执行入口与证据规则

从仓库根目录，在目标版本具备对应实现和依赖后执行：

```bash
python -m unittest -v test_project.py test_rag test_acceptance
npm run test:harness
npm run spec:validate
```

命令为现有测试入口，需要按 TASKS 补充缺失断言；缺测试文件/依赖应记录缺口，不能跳过后宣布通过。图谱测试必须实际使用 LightRAG/NetworkX/向量库，模型服务可在 L2 模拟。输入边界/版本竞态用可控服务或注入点复现，避免只依赖碰运气并发。

接口验证按 OpenAPI 检查请求与响应，再核对 DB/索引副作用；合约合法不代表业务正确。UI 人工/浏览器验证独立于 HTTP 自动测试。真实服务验证不包含在上述模拟测试通过结论里。

证据放专用测试输出目录，命名包含运行编号/用例号；仓库只提交脱敏摘要及必要附件。每条记录至少含代码 commit、环境、时间、命令/步骤、预期、实际、HTTP/code、状态及证据路径。修复后以新 commit 复验受影响断言。

## 06｜固定题集质量门槛（L3/L4）

每次在空库导入固定 8 份资料，记录真实模型/Embedding 版本及语料哈希，构建后运行 20 题。BM25、retrieve 和 generate 分开记录，保持同一语料/模型/候选预算；禁止拿不同配置的最好结果拼成一轮。

| 指标 | 分母与判定 | 首版门槛 |
| --- | --- | --- |
| 三路检索证据完整性 | Q01—Q12：retrieve 最终最多4段是否覆盖 required_documents；不把未返回候选池当命中 | 至少11/12题完整覆盖 |
| 有答案题完整回答 | Q01—Q12：generate 最终回答包含全部必要事实、引用对应原文，模型实际见过证据 | 至少10/12题合格 |
| 无答案题 | Q13—Q16：明确资料不足、不凭常识编事实；有无无关候选不影响判定 | 4/4 |
| 冲突题 | Q17—Q20：说明冲突，呈现双方值，引用 D05和D06，不擅定优先级 | 4/4 |
| 来源结构 | 所有生成的引用 ID 必须来自本轮，历史/当前证据不混版 | 合法率100%，混版0次 |
| 事实支持 | 全部20题的事实断言均受提供原文支持，冲突或不足可直接说明 | 无未受支持事实断言 |

两名评审不是首版必需；执行人逐题记判断理由及原文，争议记录为未通过待复核，不能为达标修改题目。必要事实可以等义表述，不要求与 expected_facts 逐字匹配。报告单次结果与失败案例，不以小样本声称普遍优越性。

延时、API用量/费用逐题记录；未知用量注明实际原因（服务未提供或适配器未采集），不得填0。若真实服务无法连接/无凭据，L3/L4=BLOCKED，仍可完成工程演示，但不能声明正式首版全部验收通过。
