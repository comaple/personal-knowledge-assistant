## 01｜产品目标与问题

面向需要长期积累和使用个人资料的用户，建立一个个人知识管理系统。用户可以收集资料、记录笔记、组织主题、发现知识关联，通过搜索和问答重新找到并使用已有知识。

项目解决以下问题：

- 资料散落在不同文件中，缺少统一入口，积累后难以重新找到。
- 资料之间缺少组织和关联，相近主题以及跨文档线索不容易被发现。
- 用户需要基于自己保存的资料得到回答，并能够回到原文核对。
- 已积累知识需要持久保存、修改和导出，避免只存在于一次聊天中。

**核心价值：让个人知识能够持续积累、有序组织、随时找回，并在需要时用于解决问题。**

产品主线为：**收集 → 整理 → 关联 → 检索 → 使用 → 持续更新。**问答是使用知识的一种方式；教程是配套交付物。

## 03｜用户与使用场景

主要用户是有持续资料积累需求的个人，例如研究者、开发者、内容创作者或自主学习者。首版使用者与维护者可以是同一人，不设计团队协作流程；日常使用应在浏览器中完成，无需理解 DSH 或索引实现。

典型场景：

- 保存项目说明、课程资料或个人笔记，修改标题和正文，用标签组织主题。
- 忘记原文措辞时，通过语义搜索找到相关内容；需要串联信息时使用图谱和问答。
- 核对答案来源，将整理后的资料导出，持续维护自己的知识资产。

跨文档验收示例使用虚构资料：

1. 《摄影课说明》：摄影课相关事务联系“青松教务”。
2. 《教务服务说明》：青松教务受理退课，申请需在开课前至少 72 小时提交。
3. 用户问：“摄影课退出申请最晚什么时候交？”

系统需要检索到两份资料，识别“课程 → 教务 → 退课条件”的关联，回答期限并展示两份原文。这个场景用来说明链路，不预设任意真实模型必然成功。

同时必须支持更简单的路径：用户不配置 Key，也能导入资料并用关键词检索；界面明确说明当前只有本地关键词能力。

## 04｜范围与交付物

### 首版范围草案（P0，待评审）

- 导入、去重、列出、删除 TXT/Markdown；保留可定位的原文片段。
- 创建和编辑文本笔记，更新资料标题与正文；编辑正文后同步失效派生索引。
- 用标签整理资料，按标签筛选；没有标签的资料仍能正常检索。
- SQLite 保存文档、片段、会话、消息和已返回的 DSH 执行轨迹。
- DSH 管理单轮模型—工具循环；工具限制为知识库读操作。
- 关键词、文本向量、实体关系三路召回；失败或缺配置时说明当前实际能力。
- 知识图谱及向量索引的构建、状态、失效和重建流程。
- 跨文档图谱检索；答案引用可打开原文，路径可以追溯到原文。
- 可检查图谱、证据和工具记录的简单界面。
- 导出原文、笔记及标签元数据；说明应用数据的备份和恢复方法。
- 系统安装、配置、使用、排错及维护教程。
- 与 PRD/Spec 对应的任务及验收记录，验证后再交付仓库更新。

### 后续候选（P1，首版不承诺）

PDF/OCR、网页自动采集、附件、富文本编辑、文件夹与复杂分类体系、完整编辑版本历史、增量图谱、自动清理旧索引、持久化任务队列、跨轮指代与长期记忆、多用户、云端同步。

**明确不承诺：**互联网问答、无限规模、零成本、图谱事实全正确、自动事实核验、删除文档即擦除所有历史副本。

## 05｜功能需求与验收场景

每项验收在冻结配置的测试环境中执行；“目标”表示未来验收条件，不表示当前已通过。

| 需求 | 优先级 | 行为与 Given / When / Then 验收 |
| --- | --- | --- |
| FR-01 资料导入 | P0 | Given UTF-8 TXT/MD；When 上传合法文档；Then 原文和有序片段入库。重复内容不增加文档；空文件、错误类型、NUL、超过 1 MB 的文件返回可读错误，且不产生半份数据。 |
| FR-02 持久化 | P0 | Given 已导入资料及已完成的一轮问答；When 应用正常关闭后重启；Then 可读取资料、消息、引用快照和已保存轨迹；导入或问答落库失败时不留半个事务。 |
| FR-03 本地关键词检索 | P0 | Given 无模型 Key、无图谱索引；When 导入资料并用文档关键词检索；Then 返回带来源的本地候选，不调用模型，清晰显示关键词检索状态。 |
| FR-04 索引管理 | P0 | Given 模型和 Embedding 配置有效且有资料；When 主动构建；Then 显示任务和索引状态。构建失败保留旧已发布索引；资料或模型配置变化后旧索引不参与当前检索。 |
| FR-05 多路召回 | P0 | Given 索引就绪；When 检索；Then 实际执行关键词、文本向量、图谱召回，保留通道来源并去重；某通道失败可降级且显示原因，不把降级结果标为完整多路成功。 |
| FR-06 跨文档图谱检索 | P0 | Given 两份含关联实体的示例资料；When 提问跨文档问题；Then 可查看实际图谱接口，执行有界计划并检查路径；空结果可在预算内修正，找不到时说明证据不足。 |
| FR-07 DSH 回答与引用 | P0 | Given 检索有原文；When 生成答案；Then DSH 通过已注册工具获得资料，输出仅使用返回的来源 ID；不存在的引用或未执行成功检索的答案不得当作正常成功答案。引用合法不等于事实自动核验。 |
| FR-08 图谱与原文检查 | P0 | Given 可用图谱；When 点击展示的实体或关系；Then 能查看关联原文，显示图谱为自动抽取结果；限制展示数量时说明是局部视图。 |
| FR-09 会话与轨迹 | P0 | Given 新建会话并问答；When 查看历史；Then 区分用户消息、答案、来源和工具执行；删除会话级联删除其消息与轨迹。首版旧消息不自动加入新一轮模型上下文。 |
| FR-10 删除与过期保护 | P0 | Given 某资料已建索引；When 删除该文档；Then 立即停止把它作为当前检索证据，图谱和向量索引失效；历史快照与旧索引文件的保留规则需在界面或教程说明。 |
| FR-11 故障可解释 | P0 | Given Key 缺失、超时、服务异常或检索失败；When 操作；Then 返回对应错误或降级状态，不能把服务失败描述成资料确定不存在；后续仍可继续使用应用。 |
| FR-12 系统使用与维护 | P0 | Given 一份干净检出及符合条件的环境；When 按教程操作；Then 能完成资料管理、本地检索和配置后的图谱/DSH 流程，并能按说明备份数据；记录配置与验收环境。 |
| FR-13 笔记与资料编辑 | P0（新增建议） | Given 新笔记或已有资料；When 保存合法标题和正文；Then 内容持久化、当前搜索反映新内容，正文改变时旧图谱/向量失效；保存失败保留原资料。已保存历史答案仍保留当时引用。 |
| FR-14 标签组织 | P0（新增建议） | Given 资料列表；When 增删标签并按标签筛选；Then 只显示符合条件的资料；多标签可同时属于同份资料，改标签不改原文、不触发全文重建。标签首版只用于管理和筛选。 |
| FR-15 知识导出 | P0（新增建议） | Given 已保存的资料和笔记；When 导出；Then 获得可独立阅读的 Markdown 原文及标题/标签元数据，内容与导出快照一致，不包含 Key。导出失败不修改本地数据。 |

## 06｜非功能需求

| 需求 | 目标与衡量方式 |
| --- | --- |
| NFR-01 本地边界 | 首版只监听 loopback；不提供公网访问、账号体系或任意文件浏览。密钥不出现在 API 响应、前端、仓库和示例轨迹中。 |
| NFR-02 工具权限 | DSH 仅注册白名单知识库工具；模型不能通过工具运行 shell、任意 SQL/Cypher 或写文件。文档中的指令按资料处理。 |
| NFR-03 有界执行 | 问题、文档、片段数、候选数、图遍历和进程时间都有明确限制，具体值见 Spec；步数限制不冒充总 API 次数或费用上限。 |
| NFR-04 数据一致性 | 不读取过期派生索引；失败构建不能覆盖好版本；引用来源必须能对应原文或明确标为历史快照。 |
| NFR-05 可复现 | 依赖版本、配置项、运行环境、模拟与真实验证分开记录；不将 skipped 测试计入完整通过。 |
| NFR-06 可用性 | 桌面与 390px 宽屏幕可完成核心流程，无横向溢出；长文本可读、按钮状态清楚、等待和失败有反馈。 |

## 07｜成功指标与验证分层

以下均为**验收目标，当前未宣告达成**。

| 指标 | 目标 | 测量与约束 |
| --- | --- | --- |
| 核心流程可完成性 | 冻结验收用例中的导入、笔记、标签、检索、构建、问答、重启、导出、删除全部通过 | 按最终确认范围验收；核心用例不能通过跳过依赖来判定成功 |
| 来源和一致性 | 验收答案引用 ID 合法率 100%；过期索引被使用次数为 0 | 只衡量结构与版本；语义是否受支持另行人工核对 |
| 故障透明度 | 规定的缺配置、通道失败、重排失败、超时场景均显示真实状态 | 需要接口记录和界面证据；不以日志存在代替用户反馈 |
| 真实质量 | 建议冻结至少 20 题，包含关键词、改述、多跳、无答案及冲突题，每题有证据标注 | 报告各类证据召回和答案支持情况；通过阈值待小样本试测后确认，不宣称已优于基线 |
| 日常使用与可迁移性 | 干净安装可完成一次完整知识管理流程；导出资料可在系统外打开并核对正文与标签 | 无 Key 路径与真实服务路径分别记录；日常资料操作不需要终端命令 |

验证分层：L1 静态和单元检查；L2 真实框架加模拟服务的链路测试；L3 真实模型/Embedding 冒烟；L4 固定问答集质量及成本评估。L2 不能替代 L3/L4。

## 08｜用户操作与信息设计

主流程：**导入资料或创建笔记 → 编辑并用标签整理 → 按需构建图谱与向量 → 搜索或问答 → 核对来源 → 更新或导出知识。**

- 资料列表是主要入口，提供新建笔记、导入、编辑、标签筛选、删除和导出；问答与图谱作为使用知识的入口。

- 首屏区分“本地关键词可用”“图谱/向量待构建”“完整检索就绪”，避免一个绿色状态代表所有能力。
- 构建前说明哪些数据会发送到所配置的服务；索引就绪后的检索也可能调用模型与 Embedding，不能把“只检索”标为“完全离线”。
- 答案区域突出来源和降级信息；工具详情可展开，默认不让初学者面对大段内部 JSON。
- 图谱展示帮助理解实体联系；旁边保留“自动抽取，需核对原文”的说明。
- 会话记录用于回看，不宣称模型记住了历史；删除资料与删除历史是两种操作。

## 10｜开放问题与风险

| 编号 | 待定问题 | 建议 / 影响 |
| --- | --- | --- |
| Q-01 | 首版知识组织是否采用文本笔记与标签？ | 建议纳入基本闭环；复杂目录、富文本与版本历史后续扩展 |
| Q-02 | 真实 DSH、抽取/重排与 Embedding 使用哪个服务和版本？ | 保留候选配置，不把示例别名视为长期可用承诺；影响费用、连通性和可复现性 |
| Q-03 | 真实问答质量的验收阈值及预算？ | 先冻结题集与证据，试测后约定；未定前不能发布质量优越性结论 |
| Q-04 | 本地运行、TXT/MD 与文本笔记、500 片段规模是否满足首版？ | 建议作为第一版验证规模；个人长期积累可能超限，需要后续评估容量与性能 |
| Q-05 | 历史及旧索引保留多久，是否需要一键物理清除？ | 首版说明保留和手动清理；自动清理作为后续项，删除需求有变化时先修订规格 |

主要风险：实体抽取错误会形成错误路径；复杂多跳问题可能耗尽 DSH 预算；内容重排会增加延时和费用；外部模型版本漂移影响结果；本地文件索引不适合大规模并发。应对方式是来源核对、有界执行、显式降级、配置指纹与小规模验收，不承诺通过图谱消除幻觉。
