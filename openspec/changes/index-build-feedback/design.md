# Design

## Context
现有IndexJobs使用communicate等待30分钟，stdout最终JSON，stderr是后端日志。手机隐藏侧栏，因此主区域需要独立反馈。现有用户构建不被中断。

## Goals / Non-Goals
展示真实过程和可操作提示；不更改检索/问答策略，不显示虚构剩余时长或总体百分比。

## Decisions
构建子进程通过可信生成的临时进度文件原子写入白名单字段。异步观察LightRAG doc_status，去重输入对应的全部SQLite片段按processed计数；校验与发布另用不定进度阶段。IndexJobs只接受合法phase及有界整数，终态在communicate结束并确认ready后设置，清理临时文件。

Job添加可选progress对象以兼容旧响应/测试。前端2秒轮询、独立1秒耗时刷新；失败3秒重试，保留状态并提示连接中断。构建请求pending立即禁用按钮；最终状态优先于旧索引的message。主区域提供指南与构建卡，移动端同样可见；DOM文本使用textContent。

## Risks / Trade-offs
进度文件暂无记录或损坏 → 保留最后合法进度并显示准备/处理中，不显示假数；进度写入失败不破坏构建，仅失去计数。处理计数到总数后仍需校验 → 明确阶段，不提前100%。后台停止/重启 → 只依据当前服务实际任务及已发布索引，不复活旧任务。

## Migration Plan
无数据库迁移；新增接口字段兼容旧消费者。隔离测试处理计数/终态与Chrome刷新、移动、轮询中断及指引；已有构建完成后重启应用，以原数据库/索引继续服务。凭据不进入进度文件或提交。

## 后续用户增量

单篇构建沿用同一全局原子索引指针：复用经摘要验证的旧LightRAG代，清除不再有效的backend doc，保留已有processed片段，仅插入目标文档；全库构建处理全部。manifest v3允许覆盖当前片段的非空子集，旧v2仍要求全覆盖；提供覆盖文档ID供UI说明。全局revision/CAS、来源活性与完整文档覆盖校验保持。测试验证第二篇不重复抽取第一篇以及编辑/删除时旧来源剔除。

Agent接口复用检索服务与资料写入，新增无会话路由和只读OpenAPI下载；仅loopback，沿用Host/Origin，不增加远程认证或公网部署。

AI命名在保存成功后执行，使用Chat Completions与最多3600字符摘录；命名请求可选，默认API不开启、界面显式选项默认开启。去重不调用模型，模型失败保留资料与原名，乐观版本保存避免覆盖用户并发编辑；原文不会用于标题而重切块。
