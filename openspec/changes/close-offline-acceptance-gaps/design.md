# Design

## Context

参见 proposal.md 的动机与范围。当前SQLite schema2与HTTP契约已实现，验收缺口集中在故障、并发和持久化组合。迁入前已有11项新增离线回归及部分RAG/DSH测试通过，未据此改变完整用例状态。

## Goals / Non-Goals

**Goals:** 在既有行为边界内补齐可复现证据，消除已重现的脱敏缺口和仅发终止信号的清理缺口，使测试、正式验收及OpenSpec任务状态一致。

**Non-Goals:** 不改变数据库schema/HTTP契约，不实现新的Agent循环，不把模拟服务当成真实权重，不自动闭合缺服务的AC-07/L3/L4。

## Decisions

1. **开发工具固定版本。** 将OpenSpec1.16.1放在devDependencies，使用npm scripts执行；应用继续用DSH，OpenSpec不进入请求路径。保留doc/的产品/接口/验收基线，openspec/按实际变更积累行为规格；整体复制PRD会产生两份容易漂移的总规格，因此不采用。
2. **模型返回边界统一脱敏。** Python适配层对完整结果递归处理所有字符串与对象键，再验证引用、返回及落库。只处理events值已被回归证明会泄漏答案和键；字符串替换可审计且无需推测各provider错误格式。按Key长度降级没有依据，移除原8字符门槛。
3. **两级工具终止。** 工具期限或stdout超限先终止；1秒后按PID父子关系清理仍存活进程。POSIX需要枚举子孙，因为查询进程可以创建自己的session，仅kill进程组不够；Windows沿用taskkill/T。整轮Python外层继续独立清理DSH整棵进程树。
4. **可控故障替代长时间盲等。** 生产默认截止不变；测试通过可信的内部常量/调用参数缩短截止，实际创建会忽视SIGTERM或独立会话的进程验证清理与恢复。绝不把截止参数暴露成模型工具输入。
5. **事务与界面分别验证。** 用同步屏障确定导出与修改的先后，SQLite实际WAL快照验证一致性；用触发器注入第二消息/轨迹/导出写入失败。Chrome独立验证历史引用不重新取已删原文、大图二次裁剪和390px布局，保留脚本服务标识。

## Risks / Trade-offs

- 短Key可能与普通词语重合 → 凭据保护优先；用户不应把凭据作为知识正文；脱敏后仍需通过结果校验。
- 清理时进程可能自然退出 → 仅对本轮已知PID树发信号并容忍进程已不存在，测试检查独立会话后代；不扫描/终止无关应用。
- 模拟模型可验证执行和权限，无法证明真实模型面对注入或冲突时的语义表现 → L3/L4明确保持BLOCKED，保留固定20题与人工判定标准。
- 文档/工作流状态漂移 → 报告绑定实际提交，任务勾选需证据，OpenSpec validate加入CI；artifact文件存在不能代替测试通过。

## Migration Plan

安装开发依赖后加载项目内Codex技能；新工作先形成增量需求再实施。迁入时已有改动由proposal如实说明。代码变更不迁移用户库；应用与测试提交后从独立检出复验，后续文档提交仅更新证据。必要时可回退应用提交；原doc/基线与用户数据均保留。
