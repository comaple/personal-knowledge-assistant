# Design

## Context
沿用doc/VERIFY第06节及8份虚构语料。DSH使用Messages接口；LightRAG使用Chat Completions；Embedding使用本地Ollama的BGE-M3 1024维。

## Goals / Non-Goals
执行真实端到端验收并启动可使用服务。不更换冻结题集、不凭离线结果推断真实质量，不创建正式Release。

## Decisions
使用隔离数据库和8502端口，与日常8501服务分离。保留模型输出和检索来源逐题审查；未知总用量/费用标null。Key从忽略的0600 .env加载，报告不包含环境原始值；每次提交前对暂存区执行精确匹配扫描。

## Risks / Trade-offs
- 外部服务超时或模型未达标 → 保留真实错误与失败题，不改门槛；定位后复验。
- 下载/首次加载耗时 → 单独记录连通测试，应用预算保持原值。
- 固定20题只代表该配置和语料 → 报告明确样本边界。

## Migration Plan
无需数据迁移。测试库保留在忽略目录；日常资料库不混入测试数据。失败停止测试实例并保留日志；最终启动日常服务。任何行为修复须先补增量规格。

## Observed defect and correction
真实测试中20题生成均在启动阶段失败：DSH CLI拒绝项目.env中的DSH_BASE_URL，即使已存在于继承环境也拒绝。将DSH实际processCwd放在本轮临时home，保留逻辑cwd与插件绝对路径；应用Python仍负责.env白名单加载并继承环境。避免删除用户配置或更改密钥保存方式。增加含禁止变量.env的隔离项目回归，修复前须失败，修复后工具调用完成。

第二轮实际输出Q10追加“陈舟并不负责验收”，原文未明示排他责任，判定未受支持事实，本轮不能通过。收紧通用回答原则：最少必要事实、不从未提及或角色分工推出否定，计算标明推算。完整重测20道生成题；检索模块、RAG配置、语料及候选预算不变，独立保留检索结果，不挑选不同配置最佳值。
